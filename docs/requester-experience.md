# دید درخواست‌دهنده و فید خانه

## درخواست‌دهنده (`requester`)

- **درخواست‌های کار:** ساخت با `request.create`؛ پیگیری وضعیت روی کارت درخواست.
- **پروژه:** بعد از تریاژ، `GET /requests/projects/{id}` برای درخواست‌دهنده **فقط‌خواندنی** است (خلاصه، کمپین‌های وصل، لینک گزارش). ساخت پروژه یا تریاژ ← ۴۰۳.
- **گزارش کار:** `GET /reports/work` با اسکوپ `self` — فقط درخواست‌ها و پروژه‌های مرتبط با خودش.
- **قیمت و پست‌ها:** منوی «قیمت و پست‌ها» برای مدیر و نقش‌های مارکتینگ (نه مالی خالص).

ارزیابی UX با کاربر مصنوعی (Playwright): [`synthetic-users-goals.md`](synthetic-users-goals.md).

## فید خانه (`/`)

منطق در `frontend/src/lib/focus.ts` و `HomePage.tsx`:

| KPI / بلوک | شرط دیدن |
|------------|----------|
| منتظر / دیرکرد | همهٔ کاربران واردشده |
| پروژه‌ها | `request.*` یا `task.read` |
| نیاز به پاسخ | `conversation.read` |
| قیمت‌ها | `price.approve` (یا legacy `price.write`) |
| پست‌ها | `campaign.read` (موضوع گفتگو) |

مسیر «همه چیز جمع است» (`caughtUpTarget`): اول درخواست‌ها، بعد قیمت، بعد پرفورمنس/موضوع گفتگو، بعد خودروها، پیش‌فرض کارهای من.

ناوبری روزمره: `dailyPaths` همان فایل — نقش `performance_marketing` تقویم و پروژه نمی‌بیند؛ `marketing_manager` تقویم + کمپین پرفورمنس + شیت.

## همکاری روی خودرو (مثال دمو)

```text
فروش Camry 2024
رضا ← پیگیری پرونده (case.read، نه CRM)
سارا ← آماده‌سازی آگهی
```

مشتریان (`/customers`) فقط `org.admin`؛ فروشنده از پرونده و کار مشترک پیگیری می‌کند.
